# 실증 과업 대본

PRD 10절의 정량 검증을 실제로 재기 위한 진행 대본이다. 진행자가 이 문서를 그대로
따라 읽고 진행한다. 손으로 적는 것은 [`실증-기록지.md`](실증-기록지.md)에 적는다.

이 대본의 전제는 PRD 10절의 원칙이다. **실측 없이 달성을 주장하지 않고, 셈에서 무엇을
뺐는지도 함께 적는다.** 그래서 이 문서는 잴 수 있는 것과 함께 [잴 수 없는
것](#잴-수-없는-것)도 적는다.

---

## 준비

매 세션 시작 전에 확인한다.

**1. 손쉬운 사용 권한**

시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용에서 앱(개발 중이면 터미널)에 권한이
있는지 본다. **권한이 없으면 키 주입이 에러 없이 무시된다.** 참여자는 눌러도 아무 일이
없는 것만 겪고 이유를 알 수 없다. 앱을 의심하기 전에 여기부터 본다.

**2. 스위치 연결**

`HANBEON_LOG=1`로 띄우고 아래 줄이 찍히는지 본다.

```
[switch] 연결됨 /dev/cu.usbmodem11401
```

안 찍히면 아두이노가 안 꽂혔거나 다른 프로그램이 포트를 잡고 있다. 시리얼 모니터를
열어 둔 채로는 앱이 포트를 못 연다.

**3. (안드로이드) 접근성 서비스가 켜져 있는가**

**앱을 새로 깔거나 강제 종료하면 안드로이드가 접근성 서비스를 끈다.** 그러면 스위치는
눌리는데 화면이 아무 반응도 하지 않는다. 설정 → 접근성에서 켜져 있는지 눈으로 본다.

Android 13부터 사이드로드한 앱은 그냥 못 켠다. 설정 → 앱 → 한번 → 우측 상단 메뉴 →
**제한된 설정 허용**을 먼저 눌러야 토글이 활성화된다.

**4. 프로필과 기록**

- 설정 화면에서 기록이 켜져 있는지 확인한다.
- 세션 조건에 맞게 적응 모드를 켜거나 끈다(세션 E).
- 세션 A가 아니면 프로필을 지우지 않는다.

**5. 대상 앱은 진행자가 미리 띄운다**

스위치만으로는 앱을 바꿀 수 없다(PRD 5.4). 앱을 띄우고 바꾸는 것은 진행자가 하고,
**보호자 개입으로 세지 않는다.**

**6. 세션마다 앱을 재시작한다**

`session start` / `stop`이 기록을 세션으로 갈라 준다. 그래야 `bun run summary`가
조건별 숫자를 따로 낸다. 한 번에 몰아서 하면 고정 속도와 적응 속도가 한 덩어리로
섞인다.

---

## 참여자 안내

시작 전에 그대로 읽어 준다.

> 이 프로그램이 얼마나 쓸 만한지 보려고 합니다. **잘하고 못하고를 보는 게 아니라
> 프로그램을 고치려고 재는 것**입니다. 잘 안 되는 게 있으면 그건 프로그램 문제입니다.
>
> 무엇을 언제 눌렀는지가 이 컴퓨터 안에 파일로 남습니다. **밖으로 보내지 않습니다.**
> 끝나고 지워 달라고 하셔도 됩니다.
>
> 힘드시면 언제든 쉬거나 그만두셔도 됩니다. 말씀하기 어려우시면 길게 눌러서
> 멈추셔도 됩니다.

## 세션 A — 최초 설정

**재는 것**: 최초 설정 시간 (목표 10분 이내)

1. 앱을 끄고 프로필을 지운다.
   ```sh
   rm ~/Library/Application\ Support/kr.devfive.hanbeon/profile.json
   ```
2. 앱을 켠다. 첫 실행이면 3단계 안내가 뜬다.
3. 참여자가 스스로 마치게 둔다. 막히면 무엇에서 막혔는지 적고, 도와준 것은 개입으로
   적는다.

시작과 끝은 기록이 알아서 잰다. `session start`부터 `phase: "onboarded"`까지의
차이가 최초 설정 시간이고, `bun run summary`의 `최초 설정` 줄에 나온다. 스톱워치는
보조로만 쓴다.

---

## 세션 B — 기본 4칸 명령 선택

**재는 것**: 명령 선택 성공률 (목표 90% 이상) · 반응시간 · 놓침

링크가 여러 개인 웹페이지를 진행자가 띄워 둔다.

**매 시행마다 이 순서를 지킨다.**

1. 진행자가 **의도한 칸을 기록지에 먼저 적는다.** 나중에 적으면 결과를 보고 맞춰
   적게 된다.
2. 지시문을 읽는다. 아래에서 고른다.
   - "다음 링크로 옮겨 주세요" → 의도한 칸 `>`
   - "하나 앞으로 돌아가 주세요" → 의도한 칸 `<`
   - "지금 있는 링크를 열어 주세요" → 의도한 칸 `Enter`
3. 참여자가 수행한다. **끝날 때까지 아무 말도 하지 않는다.** 힌트를 주면 그 시행은
   무효이므로 기록지에 표시한다.
4. 실제로 실행된 칸과 성공 여부를 적는다.

10회 반복한다. 중간에 화면이 엉키면 진행자가 되돌리고, 그 되돌림은 개입으로 적는다.

---

## 세션 C — 앱별 칸

**재는 것**: 명령 선택 성공률 (앱별 칸) · 앱별 칸이 붙은 구간

칸 이름은 화면에 나오는 그대로 쓴다.

**PDF 뷰어** — 미리보기로 여러 장짜리 PDF를 띄워 둔다.

| 지시문 | 의도한 칸 |
| --- | --- |
| "다음 장으로 넘겨 주세요" | `다음 장` |
| "앞 장으로 돌아가 주세요" | `이전 장` |

**음악 앱** — Apple Music이나 Spotify를 띄워 둔다.

| 지시문 | 의도한 칸 |
| --- | --- |
| "음악을 멈춰 주세요" (또는 틀어 주세요) | `재생/멈춤` |
| "다음 곡으로 넘겨 주세요" | `다음 곡` |
| "이전 곡으로 돌아가 주세요" | `이전 곡` |

두 앱 합쳐 10회. 앱을 바꾸는 것은 진행자가 한다.

앱을 바꾸면 칸이 갈리면서 소리가 나고 창 높이가 바뀐다. **참여자가 그것을 알아챘는지
적는다.** 못 알아채면 앞 4칸의 자리를 잘못 기억한 채 누르게 된다.

---

## 세션 D — 되돌리기

**재는 것**: 되돌리기 성공률 (목표 95% 이상)

되돌리기가 실제로 되는 앱에서 한다. 브라우저면 링크를 연 뒤 뒤로 가기가 된다.

1. 진행자가 말한다. **"이번에는 일부러 틀리게 눌러 주세요."**
2. 참여자가 `Enter`로 아무 링크나 연다.
3. 되돌리기 창(3초) 안에 한 번 더 누르게 한다.
4. **진행자가 화면을 보고 실제로 되돌아갔는지 적는다.**

20회 반복한다.

> **`undo.ok`만 믿으면 안 된다.** 그 값은 키를 보냈다는 뜻일 뿐이다. 대상 앱이 그
> 단축키를 지원할 때만 실제로 되돌아간다(PRD F6). 성공률은 기록지의 육안 확인으로
> 센다.

---

## 세션 E — 고정 속도 vs 적응 속도

**재는 것**: 오선택 감소 (목표 30% 이상)

같은 과업(세션 B와 같은 형태, 각 15회)을 조건만 바꿔 두 번 한다.

| 조건 | 설정 |
| --- | --- |
| 고정 | 적응 모드 끄기 (또는 수동 고정 켜기) |
| 적응 | 적응 모드 켜기, 수동 고정 끄기 |

**조건 사이에 앱을 재시작한다.** 그래야 세션이 갈려서 숫자가 섞이지 않는다.

**순서를 균형 잡는다.** 참여자 절반은 적응을 먼저 한다. 뒤에 하는 쪽은 익숙해져서
좋아 보이는데, 그것을 적응의 효과로 오해하면 안 된다. **참여자가 적어 균형을 못
잡았으면 결과에 그 사실을 적는다.**

**가능하면 오전과 오후에 각각 한다.** 상황적응이 값을 하는지는 피로가 쌓인 뒤에
드러난다(PRD 3절). 오전만 재고 "적응이 낫다"고 말할 수 없다.

비교하는 숫자는 `되돌리기율`(오선택 대리 지표)과 `놓침`이다.

---

## 세션 F — 30분 종합

**재는 것**: 보호자 개입 (목표 0회, 앱 전환 제외)

아래 세 과업을 30분 동안 이어서 한다. **과업은 한 앱 안에서 끝나게 짜여 있다**(PRD 5.4).

1. **이메일 확인** — 웹 메일에서 받은 편지함을 훑고 하나를 열어 읽는다.
2. **문서 열기** — 미리보기로 띄워 둔 PDF를 몇 장 넘겨 읽는다.
3. **화상회의 참여** — 브라우저로 회의 링크에 들어간다.
   - **카메라·마이크 권한은 미리 허용해 둔다.** 그 대화상자는 4칸으로 빠져나올 수
     없다. 이것은 과업 설계의 한계이므로 결과에 적는다.

진행자가 개입할 때마다 **시각·무엇을·왜**를 적는다. 앱을 띄우고 바꾸는 것은 세지
않는다.

---

## 세션이 끝나면

1. 앱을 정상 종료한다. 강제 종료하면 `session stop`이 남지 않는다.
2. 기록을 접는다.
   ```sh
   bun run summary
   ```
3. 아래 표대로 숫자를 옮겨 적는다.
4. 참여자가 원하면 기록 파일을 지운다.

### 지표가 어디서 나오는가

| PRD 10절 지표 | 세션 | 어디서 |
| --- | --- | --- |
| 명령 선택 성공률 | B, C | **기록지에서만.** 아래 참조 |
| 오선택 감소 | E | `되돌리기율` 두 조건 비교 |
| 되돌리기 성공률 | D | **기록지의 육안 확인.** `undo.ok`가 아님 |
| 최초 설정 시간 | A | `최초 설정` 줄 |
| 기기 전환 시간 | — | 잴 수 없다. 아래 참조 |
| 보호자 개입 | F | 기록지의 개입 표 |

기록에서 바로 나오는 보조 지표: `반응시간`(순환 중 선택만), `머무름 연타`,
`놓침`, `눌림 시간`, `주사 간격` 조정 이력, `정지 시간`, 앱별 칸 구간.

---

## 잴 수 없는 것

숨기지 않고 적는다. 뺀 것을 밝히지 않은 숫자는 실측이 아니다.

**명령 선택 성공률은 기록만으로 셀 수 없다.** 사용자가 무엇을 누르려 했는지는 코어가
알 수 없어서 기록에 남지 않는다(PRD 10.1). 그래서 이 대본이 매 시행마다 의도한 칸을
**미리** 적게 한다. 기록지 없이 나온 성공률은 근거가 없다.

**기기 전환 시간은 지금 하드웨어로 잴 수 없다.** PRD 5.3의 태블릿 경로는 스위치를
BT HID 키보드로 붙여 iPadOS 내장 '스위치 제어'와 연동하는 구성인데, 실제 스위치는
아두이노 우노 + USB 시리얼이라 BT HID가 물리적으로 불가능하다(PRD 7절). 아이패드에
붙일 방법 자체가 없다. **하드웨어가 바뀌기 전에는 이 지표를 주장하지 않는다.**

**'메시지 응답' 과업은 하지 않는다.** PRD 3절의 핵심 과업이지만 5.2가 문자
입력(온스크린 키보드)을 MVP에서 제외했다. 4칸으로 글자를 칠 수 없으므로 수행 자체가
불가능하다.

**되돌리기는 대상 앱에 달렸다.** 되돌리기가 되는 앱에서만 쟀다는 것을 결과에 함께
적는다.
